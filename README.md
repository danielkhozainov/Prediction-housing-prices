# Ames Housing: прогноз стоимости дома (CatBoost + Optuna)

Предсказание цены продажи жилья в Эймсе (Ames Housing dataset) с помощью градиентного бустинга (CatBoost) и подбора гиперпараметров через Optuna.

## Задача

- **Тип задачи:** регрессия.
- **Целевая переменная:** `SalePrice` — цена продажи дома в долларах.
- **Метрика:** RMSE (в логарифмированной шкале цен).

### Типы признаков

- **Числовые:** 35 в train, 26 в test (разница — из-за приведения типов при чтении).
- **Категориальные (object):** 43 в обоих наборах.
- **Float:** в train их мало (3), в test — много (11). Причина: некоторые целочисленные колонки (площади подвалов, количество ванных и т.п.) в test стали float из-за пропусков — pandas так обрабатывает NaN. Это типично и не ошибка.

**Практический вывод:** при построении пайплайна нужно явно приводить типы (например, `BsmtFinSF1`, `GarageCars` обратно в int, если нет NaN, либо оставить float и корректно обрабатывать пропуски). Для CatBoost это менее критично, для XGBoost/LightGBM — важно.

## Пропуски и их семантика

В датасете много колонок с большим числом пропусков, и во многих случаях это не случайные пропуски, а отсутствие признака:

- `Alley` — 91 непустых в train (очень мало) → почти у всех домов нет аллеи.
- `PoolQC` — всего 7 непустых → почти у всех нет бассейна.
- `Fence`, `MiscFeature` — очень мало непустых значений → признак редкий.
- `LotFrontage` — ~25% пропусков → это реальный пропуск данных.
- `MasVnrType/Area`, `BsmtQual/Cond/Exposure`, `GarageType/YrBlt/Qual/Cond` — пропуски часто означают «нет соответствующего элемента» (нет облицовки, подвала, гаража). Это классический паттерн Ames: пропуски несут смысл.

### Стратегия заполнения

- Для «отсутствия признака» (бассейн, аллея, гараж и т.п.) категориальные пропуски заполняем значением `'None'` (или отдельным токеном), чтобы модель могла выучить паттерн «нет такого объекта».
- Для количественных характеристик, где пропуск — это именно потеря данных (например, `LotFrontage`), заполняем медианой — лучше по группе, например по `Neighborhood`.

## Целевая переменная SalePrice

| Статистика | Значение |
|---|---|
| count | 1460 |
| mean | 180 921.20 |
| std | 79 442.50 |
| min | 34 900 |
| 25% | 129 975 |
| 50% (медиана) | 163 000 |
| 75% | 214 000 |
| max | 755 000 |

**Анализ распределения:**

- Среднее (180 921) заметно выше медианы (163 000) — признак правого скоса: дорогие дома тянут среднее вверх.
- IQR = 84 025 — довольно широкий разброс цен внутри «типичного» диапазона.
- Границы выбросов (1.5·IQR): [3 937.50, 340 037.50]; выбросов: 61 (4.18%).
- Выбросы — это не «шум», а реально существующие дорогие дома, важная часть распределения.
- Максимум (755 000) почти вдвое больше верхней границы IQR — именно эти объекты дают длинный правый хвост.

**Практический вывод:** если обучать на сырых ценах, модель будет «перетягиваться» на дорогие объекты, а предсказания для типичных домов станут менее точными. Поэтому целевую переменную логарифмируем.

## Модель и подбор гиперпараметров

**Модель:** `CatBoostRegressor` с нативной работой с категориальными признаками.

**Подбор гиперпараметров:** Optuna (TPE-сэмплер, seed = 42), 30 попыток. Вместо кросс-валидации на каждой попытке используется один holdout — это примерно в 3 раза быстрее за попытку.

```python
def objective(trial):
    params = {
        'iterations': trial.suggest_int('iterations', 400, 1200),
        'learning_rate': trial.suggest_float('learning_rate', 0.02, 0.1, log=True),
        'depth': trial.suggest_int('depth', 4, 7),
        'l2_leaf_reg': trial.suggest_float('l2_leaf_reg', 1.0, 10.0, log=True),
        'loss_function': 'RMSE',
        'random_seed': 42,
        'verbose': 0,
        'thread_count': -1
    }

    X_tr, X_val, y_tr, y_val = train_test_split(X, y_log, test_size=0.2, random_state=42)

    model = CatBoostRegressor(**params, cat_features=cat_features,
                              early_stopping_rounds=50)
    model.fit(X_tr, y_tr, eval_set=(X_val, y_val), verbose=0)
    return np.sqrt(mean_squared_error(y_val, model.predict(X_val)))

study = optuna.create_study(direction='minimize',
                            sampler=optuna.samplers.TPESampler(seed=42))
study.optimize(objective, n_trials=30, show_progress_bar=True)
```
